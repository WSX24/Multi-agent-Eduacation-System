# PPT-Agent 优化改动记录

> 日期：2026-10-03
> 范围：`agent.py`、`staged.py`
> 目标：解决「staged 架构比原 ReAct 更慢、更贵、经常产不出 PPT」的问题。

---

## 一、问题诊断

staged 架构上线后，实测 4 页《向量数据库入门》任务出现三种失败/浪费模式：

### 1. Communication trace 误判（导致导出被拒）
- **现象**：`svg_to_pptx` 报 `--quick-generate requires a passing final SVG quality report`，校验器报：
  ```
  [ERROR] Communication trace: ... missing on Slide 01, 03.
  ```
- **根因**：P2.5 文本适配阶段，模型偶发往 `design_spec.md` 的 §IX 里新增
  `### Part 2`、`#### Slide 01 — 长句拆行` 这类标题（"修正记录"段落）。
  skill 校验器把每个 `#### Slide NN` 标题都当成正式页面，发现缺 `Audience move` /
  `Relationships` → 判 blocking → 拒绝导出。
- **性质**：非确定性（同样任务，模型有时直接改原文=成功，有时新增段落=失败）。

### 2. P4 反复修复（最大的时间黑洞）
- **现象**：P4 VERIFY 一轮烧 457s（6 次模型调用），占整轮 722s 的 62%。
- **根因**：P3 写出的 SVG 文字超界 → 校验打回 → 模型反复改坐标。而文字宽度
  计算是像素级算术，恰恰最烧推理 token。

### 3. P2.5 文本适配循环（白烧钱）
- **现象**：P2.5 让模型反复"拆行/缩写"计划文案，实测 3 轮改不动，白烧 61s +
  3 次调用，最后还残留超宽。
- **根因**：拆行需要推理，low 推理下模型缩不动；而这本来就是 P3 的字数上限
  能兜住的，根本不用在计划层修。

### 4. 关思考（thinking disabled）的不确定性
- **现象**：一刀切关思考后，模型"精确遵循规则"能力丢失，非确定性地崩：
  fill spec 乱加 `## forbidden` 行、写页用图标引用、修复时复读机。
- **结论**：`disabled` 不适合 staged（每个阶段都要精确遵循 schema/规则）。

## 二、改动清单

### `agent.py`

| 位置 | 改动 | 原因 |
|---|---|---|
| `PPTAgent.__init__` | `thinking` 默认 `"default"`；`reasoning_effort` 默认 `"low"` | 不再一刀切关思考；`low` 是 README 实测「0 错误 + 快 15% + 质量持平」的安全折中 |
| CLI `--thinking` | 默认值 `"default"` | 同上 |
| CLI `--reasoning-effort` | 默认值 `"low"`（原 `None`） | 同上 |

### `staged.py`

| 位置 | 改动 | 原因 |
|---|---|---|
| `FIT_PROMPT` | 加「硬性红线」段 + `{integrity}` 段 | 禁止模型新增 `Slide NN` 标题/Part 2 段落（*注：此 prompt 现已随 P2.5 重写而废弃，见下） |
| `SPEC_REPAIR_PROMPT` | 加「Slide NN 编号唯一性」修正要点 | 教模型遇到 communication trace 报错时删多余块而非补字段 |
| 新增 `_outline_integrity_errors()` | 复刻 skill 校验逻辑 + 检测 Slide 编号重复 | 修 communication trace 误判 |
| 新增 `_per_role_char_budget()` | 从标定表算每字号单行最大汉字数 | 把像素算术从模型手里拿给代码 |
| `PAGE_PROMPT` 第 2 条 | 「内容要充实」→「内容简洁、宁短勿长」 | 降低超界概率 |

| `PAGE_PROMPT` | 新增 `{char_budgets}` 字数上限段 | P3 写页时直接给每行字数硬约束 |
| `REPAIR_PROMPT` | 加「icon not found → 手画原生图形」处理 | 修复时能正确响应图标缺失 |

| `phase_execute()` | 传 `char_budgets` | 让 P3 拿到字数上限 |

## 三、核心思路（为什么这样改）

**把「算术」从模型手里拿给代码。** SVG 超界/图标缺失/结构破坏这些校验失败的
根因，都是模型要做"精确计算或精确遵循"，而这恰恰最烧推理 token。

- **字数上限**：代码用 `text_measure` 标定表算好"body 每行 ≤44 字、title ≤24 字…"
  直接喂给模型，模型只需"数字数"，不需要推理 → P3 一次写对 → P4 不用修。
- **结构完整性**：代码直接复刻 skill 的 communication trace 校验，P2.5 纯代码
  检测，发现重复 Slide 编号/缺必填行才调模型修一次。
- **推理强度**：`low` 保留够用的基础推理（填 spec 不乱加行、能数字数），
  又比全开省大量 token；`disabled` 则太激进（连"别乱加行"都守不住）。

|---|---|---|---|
| 总耗时 | 402s | 722s | **203s** |

**结论**：现在 staged 全面优于原 ReAct——耗时快一半、输入 token 省九成、

| execute 阶段用 `deepseek-v4-pro` | 8 页 P3 耗时 1029s、推理 9.6 万 chunk，8 页全错 | pro 在精确坐标排版上反复纠结（复读机），质量反而不稳定 → execute 勿用 pro |

| 参数 | 默认 | 说明 |
|---|---|---|
| `--parallel-pages N` | 1 | 并行生成；仅适合「输出少、并发友好」的模型/端点 |

对 DeepSeek 思考型模型 + 精确排版任务：**串行 + `low` 推理是实测最优**，
「并行」「关思考」「换强模型」均为负优化。

## 2026-10-10：导出失败根治——超长文字自动拆行 + 缩短指引

> 范围：`bounds_fix.py`、`staged.py`、`pipeline.py`
> 目标：根治「svg_to_pptx 导出失败」（blocking 错 = 文字超出容器），不再“总出现”。

### 问题诊断

12 页《导数的几何意义》导出被 release gate 拦下：`09_challenge.svg` 的
`challenge-box`（宽 484px）里塞了一行 28 字提示，18px 字号下每字约 19.1px，
水平溢出 25.3%（阈值 5%）→ 判 blocking。

为什么旧代码救不了：容器右边紧贴 `plot-panel`（x=544）、左边已到 x=56 边距，
所以「扩框」撞邻居回滚、「挪位」也放不下 28 字；唯一解是「拆行 / 缩短」，但
`bounds_fix` 只改坐标数字不改内容，模型 P4 又倾向整页重写 → 修复轮次用完，
导出失败。这类「文字超长 + 容器被邻居挡死」是数学课件（布局最密）的高发形态。

### 改动清单

| 文件 | 改动 | 原因 |
|---|---|---|
| `bounds_fix.py` | 新增 `reflow_overflow_text` 第四条策略：超长单行文字拆成多行 `<tspan>` | 把「拆行」这个确定性操作从模型手里拿给代码，0 次模型调用 |
| `bounds_fix.py` | 五道安全边界：仅水平溢出 / 仅单行（无 tspan）/ 仅 CJK 主导 / 拆完不超容器下边界 / 不压下方文字 | 拆行是内容改动，宁可少拆不多拆，避免换一个 checker 看不见的重叠错 |
| `staged.py` | `_auto_fix_bounds` 策略链接上第四条（嵌套→挪→扩→**拆行**） | 复用「快照→改→复验→回滚」框架 |
| `staged.py` | 新增 `_FIT_CHARS_RE`，`_solve_bounds_errors` 解析报错自带的 `≈N chars fit in W px`，给出「缩短到 ≤N 字」指引 | 拆不了的（多行挤一起）给模型明确算术指引，不再瞎扩框 |
| `pipeline.py` | self_check ⑬ 覆盖拆行策略 | 自检文案与实现对齐 |

### 核心思路

延续「把算术从模型手里拿给代码」：
- **拆行**是确定性的（报错自带每字像素、容器宽度），代码直接改，复验回滚兜底；
- **缩短文字**是语义操作、代码不能安全自动做，于是把 checker 已算好的
  「只放得下 N 字」直接喂给修复提示，让模型照着改。

### 验证

- `python bounds_fix.py --selftest`：新增 ⑯ 拆行策略、⑰ 四道安全边界，全绿；
- `python pipeline.py --check`：⑬ 扩到「扩框/挪元素/拆行三条策略」，整体 ✅；
- 真实 `09_challenge.svg` 实测：拆行策略正确拒绝（撞 y=660 结论行），
  `_solve_bounds_errors` 正确吐出「缩短到 ≤25 字」。

## 2026-10-11：几何绘图能力大扩展——从「只会 y=f(x)」到「覆盖高中几何」

> 范围：`plot_math.py`、`staged.py`、`agent.py`
> 目标：根治「函数图像之外画不了 / 辅助几何全手画」——切点飘、弦端点不在曲线上、切线飞。

### 问题诊断

`plot_math` 原来只能画 `y=f(x)`（M/L 折线）。实测（圆锥曲线专题、导数专题）：

- **弦端点不在椭圆上**：模型手画弦，端点代入椭圆方程得 0.68 ≠ 1（在椭圆内部）；
- **切线飞了**：切线不过切点（差 68px），或画成圆心高度的割线；
- **曲线画成斜直线/任意贝塞尔**：椭圆/双曲线不是函数，没有代码能力就只能手画；
- **立体几何**：正方体的棱、可见/不可见全靠手画，比例和遮挡都错。

根因一句话：**凡是超出 `plot_math` 能力范围的几何，模型自己算，必然错。**

### 改动清单

| 文件 | 改动 | 说明 |
|---|---|---|
| `plot_math.py` | `plot_geometry` 加 **多切点 `points`** + **尖点 `sharp`** | 覆盖「正负单调」「陡峭」「\|x\| 尖点」 |
| `plot_math.py` | 新增 **`conic_geometry`**：圆/椭圆/双曲线/抛物线（参数方程 + **等比例** + 焦点/顶点） | 椭圆不会变形 |
| `plot_math.py` | conic 加 **曲线上的点 `points`（参数 t）/ 弦 `chords` / 点处切线 `tangents` / 自由点 `free_points` / 线段 `lines`（可带 `arrow`）/ 交点 `intersections` / 过外点切线 `ext_tangents`** | 端点全部精确算好 |
| `plot_math.py` | 新增 **`param_curve_geometry`**：任意参数方程 `x(t), y(t)` | 摆线/心形线等 |
| `plot_math.py` | 新增 **`solid3d_geometry`**：3D 顶点/棱/面 → **正交/透视投影** + **面深度排序** + **隐藏棱判定** + 预设 | 正方体/正四面体/正八面体/棱柱/棱锥 |
| `plot_math.py` | 新增 **`revolution_geometry`**：母线绕轴旋转 → 母线 + 纬线圆 | 圆柱/圆锥/圆台/球 |
| `plot_math.py` | `compile_expr` 支持自定义自变量名（`var="t"`） | 参数曲线用 |
| `staged.py` | `plot_page_figure` 支持 `kind` ∈ function_plot / conic / solid3d / parametric / revolution | 按 kind 分派 |
| `staged.py` | 新增 **`figure_completeness_errors`** + `phase_plan` 打回重填 | 见「三层防线」 |
| `staged.py` | PLAN_PROMPT 五种 kind 的字段说明 + 硬性红线 | 告诉模型必须用哪个 |

### 三层防线

1. **代码能力**（`plot_math`）：坐标全部由代码算，模型照抄；

2. **提示词红线**（PLAN_PROMPT）：出现「切点/切线」必须 `function_plot`；出现「圆/椭圆/双曲线/抛物线」必须 `conic`；出现「正方体/棱柱/立体」必须 `solid3d`；出现「摆线」必须 `parametric`；出现「旋转体」必须 `revolution`；

3. **代码校验**（`figure_completeness_errors`）：P1 出 plan 后扫 roster，凡「内容涉及某类图形、但 figure 未声明对应 kind」的页 → **打回 P1 重填一次**（改善就采纳，没改善保留原计划）。

### 关键实测数据

| 能力 | 验证 |
|---|---|
| 圆的切线 | 切点精确在圆上，切线过切点（模型原来画在圆心高度） |
| 过外点切线（圆/椭圆/双曲/抛） | 各 2 条，切线到外点距离 **0.00px** |
| 弦端点 | 代入椭圆方程 = **1.000**（原来是 0.68） |
| 3D 隐藏棱 | 正方体从上前方看，背面 3 条棱正确判为虚线 |
| 旋转体 | 圆柱母线 + 纬线圆投影正常 |

### 验证

- `python plot_math.py --selftest`：**20 项**全绿（切点/切线/割线、多切点、尖点、圆/椭圆/双曲/抛外点切线、圆锥曲线点/弦/切线/交点、3D 预设/透视/隐藏棱、参数曲线、向量箭头、旋转体）；
- `python pipeline.py --check`：全程通过（⑫ 图像几何覆盖 conic）。

### 中途试过又回退的（便于追溯）

- **圆切线 / 公式排版**：先做了一版（`circle_tangent`、`limit_fraction`）后回退，本轮的 `conic`（含圆）是更完整的替代；
- **`--temperature` 默认 0.4**：试过降波动，回退为 `None`（用提供商默认）；
- **P1/P3 分工实验**（P1 写完整文案、P3 照抄）：导致字体/图像混乱，已回退——结论是「文案与排版强耦合，P1 看不到排版细节，不能提前定死文案」。

### 教训

**几何绘图的价值全在坐标正确性，而模型的坐标算术不可靠——凡是「算出来的东西」（交点、切点、端点、投影），都必须由代码算、模型照抄。** 这是本文件从始至终的主线（「把算术从模型手里拿给代码」）在几何领域的延伸。

## 配图过滤分级（P3 先行）

> 日期：2026-10-21（本轮）
> 范围：`image_pipeline.py`
> 起因：用户判断「图片过滤的关键词应该设优先级」。核查确认：现有词表全是
> `any(... for k in LIST)` 的平权 OR 集，弱负向词能杀死正确结果，且阈值散落
> 在 4 处魔数里。

### 目标结构（四层，本次只落 P3）

| 层 | 语义 | 判定方式 | 实现位置 |

| P0 硬否决 | 命中即淘汰 | 单条命中即 veto | `JUNK_TITLE_RE`、`_style_mismatch`、`_ok_file`、`used_texts` |
| P1 实体锚点 | 必须命中 | must-pass | `_entity_hit`（未改） |
| P2 题材覆盖 | 加权求和过线 | ≥ 阈值 | `relevance` / `_term_coverage`（未改） |
| P3 风格偏好 | **只排序，永不否决** | 排序分 | `style_preference`（新增） |

### 改动

- 新增 `STYLE_W` 权重表 + `MEDIUM_ART_HINTS` / `MEDIUM_PHOTO_HINTS` + `style_preference(row, item)`，
  返回 `(分数, 理由标签)`；**没有 veto 返回值**，从接口上保证它不能否决。

  打印每张候选的 P0/P3 明细，不联网、不改项目。

## P2 加权覆盖：只读诊断版 + 离线标定

> 日期：2026-10-21（延续上一条 P3）
> 范围：`image_pipeline.py`
> 目标：把「中文命中 1 个词即过」换成按词序加权求和，**但先不接管闸门**——
> 只并列打印「现判」与「加权会怎么判」，用真实数据定阈值。

### 为什么不能直接换

`_term_coverage` 把「雪夜古庙」里的「古庙」和「雪夜」当同权：命中一个就算过。
但阈值定太严会大面积误杀（见下面的实测曲线），所以必须先用现役产出做对照。

### 改动（全部只读，不参与任何 pass/fail）

- `_reference_terms()`：把 Reference 拆词逻辑从 `_term_coverage` 抽出来，现役闸门与
  诊断共用。**不共用会诊断出满屏假分歧**。
- `p2_weighted_coverage()`：按词序加权（首词 1.0 / 其余 0.7 / 英文专有 0.5 / 英文通用 0.2；
  近义词 ×0.7、长词 2 字前缀 ×0.5），返回 `(比例, 满分, 命中标签, 备注)`。
- `P2Diag` + `_p2_diagnose()`：取图时每张候选打一行
  `[p2-diag] P07 x.jpg: 现判=拒｜加权 0.33<0.35 → 拒｜命中 panpipe+0.5`，
  阶段末给一致/分歧汇总。整个函数包在 `try/except` 里：**诊断自己崩了也不许搞挂取图**。
- `handle_row` 里把 `accepted` 提成变量后调用诊断——控制流与原来逐字等价。
- `--audit-p2 ROOT`：扫所有已产出项目的 `image_sources.json`，重新过两套判据，
  直接量「加权会误杀几张」。只读、不联网、不写文件。
- `--p2-pass FLOAT` / `--no-p2-diag`：标定与关闭开关。

### 中途抓到的设计 bug（这条最重要）

第一版把中英文词**合并进同一个分母**，结果 15 张真实取图通过率只有 **7%**（现役 73%）。

## `rejected.json` 补文件名：把「多拦」这一侧也量化出来

- 去重键从 `text` 改为 **`(filename, text)`**：同一段元数据在不同页被拒是两件事

## `_entity_hit` 支持中文实体的人工英文别名

> 日期：2026-10-21
> 范围：`image_pipeline.py`
> 起因：`_entity_hit` 拿 Reference 的中文实体去匹**英文元数据**，中文专名对英文
> 标题必然不命中。既有规避只有 arts 行的 `query_override`，非 arts 行没有保护。
> 对账时实测：`night 荷塘 full moon lotus pond`（一张对的图）被以「实体未命中」拒掉。

### 做法：人工策展别名表，**绝不自动音译**

新增 `ENTITY_ALIASES: Dict[str, Tuple[str, ...]]`（19 个短专名）+ `_alias_hit()`。

**为什么不用拼音自动生成**：拼音把「林」变成 `lin`，而 `lin` 在拉丁文标题里到处都是
——2026-10-20 实测 `Lin` 命中 Pixabay 的 `fleur-de-lin`（鸢尾花），一张花图被当成
林冲雪战图。所以表里只收能当专名用的写法（`Lin Chong` / `Outlaws of the Marsh`）。

### 四道防线（每条对应一次真实事故或一个具体坑）

1. **按词匹配，不做子串** —— `lin` 不得命中 `fleur-de-lin`；
2. **全通用词的别名作废** —— `water margin` 两词都在 `_GENERIC_EN` 里，
   会命中河岸图（2026-10-20 事故），这种别名直接不生效；
3. **多词别名必须逐词全中** —— `wu song` 不能只命中 `song` 就放行
   （否则任何音乐图都能冒充武松）；只剔虚词（of/the/and），**不剔短实词**
   （拼音音节常只有 2~3 字母：wu/su/yu）；
4. **单词别名 ≥ 5 字母** —— 三四字母的拉丁词没有区分度。

另外**只认精确键**，不做「键与实体互为子串」的模糊回落——那会让「荷塘月色」
靠「月色」的 `moonlight` 单独过关，等于把实体门槛降成题材门槛。
复合专名（宝黛初会 / 荷塘月色）在表里显式加行。

### 影响面

| 方向 | 结果 |
|---|---|
| 放宽 | 中文短专名 + 英文元数据，这类组合以前**必败**，现在能过 |
| 收紧 | 无。别名只在**中文实体没命中之后**才启用 |
| 历史回归 | `--audit-p2` 别名开/关对照：**18 张取图结论完全一致**（0 变化） |

只在 2~4 字短专名上生效（>4 字的题材描述走原早退路径，不碰别名表）。

### 验证

- 18 条定向用例全绿：7 条该放宽的（林冲/武松/宝黛初会/红楼梦/紫藤萝/西湖/荷塘月色）
  + 8 条该拦的（fleur-de-lin、water river、folk song、chongqing、缅甸古庙、
  lake house、christmas sale、moonlight sonata）+ 3 条原路径不受影响；
- 19 实体 × 26 条噪声 = 494 组合，残留误报 **3 条**，已写进代码注释：
  - `red cliff beach australia` → 赤壁赋
  - `west lake district hangzhou office` → 西湖
  - `wisteria lane street sign` → 紫藤萝

这三条是「译名本身就是常用词」的固有代价，仍须再过 `relevance` / `_term_coverage` / P0。
比「中文意图永远配不上英文图」净收益大，但**不是零风险**——若发现误配就删对应别名。

### 怎么加新别名

在 `ENTITY_ALIASES` 里加一行即可，无需改代码。加之前先自查两件事：
① 别名里有没有全落在 `_GENERIC_EN` 的词；② 这条西文写法会不会出现在无关题材里。

## P1 配图闸门：修「无 ｜ 零校验」+「氛围词单命中即过」

> 日期：2026-10-21
> 范围：`image_pipeline.py`、`staged.py`
> 起因：赤壁赋实跑暴露两条"该拦的没拦"。

### 改了什么

**① 无 `｜` 前缀的行不再零校验**

以前 `_term_coverage` 第一行就是 `if "｜" not in reference: return True` —— 等于关掉题材
校验（赤壁赋 6 行里占 2 行）。现在：

- `_reference_terms()`：没有 `｜` 时拿**整条 Reference** 当查询；
- `_term_coverage()`：去掉早退，无 `｜` 的行照样过一遍题材覆盖；
- `run_image_phase()`：启动时点名警告
  `⚠️ 取图：2/6 行 Reference 缺 实体｜ 前缀（p07_xiao_flute.jpg、p12_moon_river_boat.jpg）`
- **空 Reference 仍放行**（旧产物里很多这种行，无从校验；该行仍受 `relevance` 约束，
  它会回退到 Purpose）。

根因其实在上游：P2 提示词从没要求过 `｜`，所以模型永远不写。

**② 只命中时间/氛围词不算命中**

实测：「月夜江面小舟」收下一张纯月亮照（标签 `月出, 月亮, 满月, 夜晚, 月夜, 气氛`），
命中「月夜」即过，而图里没有水面也没有舟。

- 新增 `_MOOD_ONLY_TERMS`（月夜/夜色/夕阳/黄昏/远景/特写/倒影…）+ `_mood_term()`；
- 规则：若**命中的中文词全部**落在该集合里 → 判不命中；命中任何对象词即照常放行；
- 故意**不收录**「雪景 / 夜景 / 景色」这类看得见的主体场景词。

**③ 提示词补上格式契约（`staged.py`）**

`IMAGE_FILL_BLOCK` 第 3 条从「中文描述 + 英文关键词」改成强制三段式
**`实体｜主题词 主题词（英文关键词）`**，写清 `｜` 的作用（少了就等于关掉实体校验），
给出正例 + 两个反例，并要求**第一个主题词写对象、不要拿氛围词打头**。
示例行同步改成 `宝黛初会｜工笔人物画 宝黛初会 红楼梦（…）`。

**④ P2 诊断对齐**：氛围词在加权里也给 0.5 折减（`P2_W_MOOD`），
否则诊断会显示 P2 比新闸门更宽松，误导读数。同时 P2 不再对无 `｜` 的行标「不适用」。

### 验证

## 配图排序：命中词数优先 + 现代气息分档（用户口径落地）

> 日期：2026-10-21
> 范围：`image_pipeline.py`
> 用户口径原文：
> > 「首先不能完全偏离关键词，比如"月夜江面小舟"，图片没中里面的任何一个词就百分百排除，
> > 如果全中就好，没有全中的话，至少得中里面的词，按中的词多优先级高。
> > 如果主题明确是古诗、古文等就尽量避免搜现代气息的图片，比如高楼大厦，
> > 但是现代的古风摄影也未尝不可。」

### 逐条落地

| 用户要求 | 实现 | 位置 |
|---|---|---|
| 一个词都不中 → 100% 排除 | `_term_coverage` 中文 0 命中且英文兜底也不中 → False | 已有，本次补文档 |
| 全中最好 / 中得多的优先 | 新增 `rank_key()` = **(命中词数, P3 风格分)**，命中数是**主键** | 新增 |
| 命中判定要一致 | 抽出 `_zh_hits()`，阀门与排序**共用同一个函数**（否则会出现「闸门说中了、排序说没中」） | 重构 |
| 尽量避免现代气息 | `_MODERN_HINTS` 拆两档（见下） | 改动 |
| 现代古风摄影未尝不可 | 「城市/现代/写真/街景」**不再硬否决**，只降权 | 改动 |

### 现代气息：拆成硬否决 + 软降权

| 档 | 词 | 行为 |
|---|---|---|
| `_MODERN_HARD_HINTS` | 摩天大楼、天际线、高楼大厦、写字楼、玻璃幕墙、航拍城市、skyscraper、skyline、high-rise | **P0 硬否决**（`_style_mismatch`） |
| `_MODERN_SOFT_HINTS` | 城市、现代、写真、街景、摩天、楼群、都市、city、urban、modern、downtown | **只降权**：一般 -1.0，古画/古文类 -2.5 |

新增 `_CLASSICAL_HINTS` / `_is_classical_row()`：诗、词牌、宋词、唐诗、元曲、楚辞、乐府、
古文、文言、古籍、古画、国画、水墨、丹青、山水、画卷、工笔、写意… 命中即视为
「古诗古文类」，**现代气息降权加倍**。

⚠️ 刻意区分：`_is_classical_row` **只影响现代气息降权**，不参与 `_is_arts_row` 的
「画种 vs 照片」扣分——否则《荷塘月色》要一张真实荷花照也会被扣，与用户意图相反。

### 排序链路统一

`fetch_web`（wikimedia/openverse 候选集）、`fetch_pixabay`（原来自有 `_tag_score` 排序）、
`--explain-style` 三处现在都按 **命中词数优先**：
- `fetch_web`：`max(items, key=rank_key)`
- `fetch_pixabay`：`rank()` 返回 `(中文命中数, 标签重合度*10 + 分辨率)`
- `--explain-style`：输出多一列 `命中 N/M`

### 验证

**排序行为**（合成候选）：需求「月夜江面小舟」——
水墨荷花图命中 0/3（风格分 6.90）**排在** 河上小舟命中 1/3（风格分 4.50）**之后**。
即"风格再好，也不能跑题"。

**现代气息**：

### 怎么避免「一页缺图 → 整册归零」（2026-10-22）

这类事故的形状是固定的：**单点资源缺失把整册产物清零**。四层防线：

| 层 | 措施 | 位置 |
|---|---|---|
| ① 上游别骗模型 | `sync_lock_images()` 只投影**磁盘上真有文件**的行（以前只按 acquire 判断，把 Needs-Manual 也列进去） | `image_pipeline.py` |

| ④ 收尾失败不阻断 | `finalize_svg` 失败降级为告警继续导出 —— **原生导出器读的是 `svg_output/`，不依赖 `svg_final/`**，它崩了没理由让整册归零 | `staged.py` |

外加**失败要可行动**（`router.py`）：导出失败时不再只打「未找到 .pptx」，而是给出
skill 项目路径、该看哪个日志、以及「SVG 已齐只差导出」时的重跑命令。

`P02 → 注入禁令`、`P01 → 配图清单`、`P05 → 空`。
`strip_unresolved_images` 单测：有图保留 / 缺图剥掉 / 外链保留。

## 新增兜底图源：浏览器搜图（必应图片，**只产候选，默认关闭**）

### 定位

### 为什么不能自动用

### 实现中踩的四个坑（都体现在代码里）

| 坑 | 现象 | 处理 |
|---|---|---|
| 裸 `murl` 正则乱抓 | 命中页面里「视觉搜索控件」的元数据，抓回一堆无关图（岳飞画像 → 北方工业大学校徽） | 只解析 `m="{...含 murl...}"` 那个 JSON 载荷，拿 murl/purl/**t(标题)** |

| 电商/素材站 | 结果被 alicdn/699pic/znzmo 之流刷屏 | 域名黑名单 + 每站最多 2 张 |
| 标题里只有 2 字巧合 | 「中国古代战车」的 2 字前缀「中国」把一堆**中国地图**放进战车候选 | 候选过滤只用**整词命中**，不套 `_zh_hits` 的 2 字前缀规则 |
