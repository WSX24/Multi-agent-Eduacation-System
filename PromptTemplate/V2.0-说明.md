# 提示词模板库 V2.0

> 分支 `PromptTemplate-V2.0` ｜ 2026-09-29
> 上游：`main`（536b9a6）。本文件讲**这一版改了什么、为什么、验证到什么程度、边界在哪**。
> 逐字实录（真实输入与输出）另见 [`REAL-RUN-2.0.md`](REAL-RUN-2.0.md)。

## 一句话

V1.0 是「一套能用的模板」；V2.0 补上的是它缺的**三块覆盖面**和**一层可离线回归的校验**——
从「写完靠人肉跑一遍看看」变成「改完能离线知道有没有退化」。

## 一、五个变化

| # | 变化 | 之前的状态 | 现在的状态 |
|---|---|---|---|
| 1 | **文科路径** | 8 个角色、5 份范文、3 个 CoT **全是理科**；文科从未被验证 | 新增 `assistant_essay`（作文/主观题批改）+ 4 个文科 CoT 片段 + 语文范文；`eval_planner --case chinese` 18/18、`eval_essay` 48/48 |
| 2 | **答疑角色 `qa`** | 既无范文也无评测，模板里**连承载提问的字段都没有** | 新增【本次提问】段 + 数学/语文各 1 例范文（两例【思路引导】都不给结论）+ `eval_qa.py`（核心断言：结论关键词不得出现在【思路引导】） |
| 3 | **可离线回归的校验层** | 断言与模型调用焊在同一进程：没 Key 就 `sys.exit(2)`，走不到断言。校验器自身的错误只能靠真跑+人眼发现（已出过 5 次，全是误报） | 新增 `replay_eval.py`（L2 回放）：把 `eval_runs/` 的真实输出当"录像"喂给现成校验器，**不需 API Key** |
| 4 | **结构统一** | `qa` / `supervisor` 用旧式 `system` 写法，`system_base.yaml` 是死文件 | 全部重写为 `sections`，死文件归档到 `_archive/`；旧格式兼容性保留并有测试保着 |
| 5 | **端到端接上** | 4 个角色的资产"备而未接"：`assistant_essay` 不在任何流程里，7 个 CoT 片段只有 `math_steps` 被引用过 | 示范流程新增**阶段 4B 作文批改**；CoT 按「学科轨道 × 用途」自动选；`--cot-table` 可查验选择表 |

### 顺带修掉的真缺陷（都是实测暴露的，不是猜的）

| 缺陷 | 后果 | 修复 |
|---|---|---|
| `teacher.yaml` 的「中等」档**不命中任何分支** | 传「中等」进去静默失效、不报错 | 补为第 5 档；差分检查证明五档输出互不相似 |
| `assistant` 的满分**由模型自编** | 模板要求「得分/满分」却从不传满分；实测 5 分题模型判 `10/10`，而旧断言 `sc[0]==sc[1]` 竟然通过 | 满分由调用方传入、写入输入契约；断言改为「分母 = 传入满分」 |
| 学情字段同源，拼出病句 | 「正确率 72%与ch01 章节测验正确率 72%」——模型以为手里有两份独立证据 | 三个学情字段拆开来源 |
| `need_example=false` 时照样出例题 | 为消除"同一个值注入两次"改成引用上文标签，模型不再就地看到 `false` | 改回内联值；`eval_unit` 56/58 → **58/58** |
| 照抄检测对 YAML 蓝图 100% 误报 | 归一化后 YAML schema 串成 158 字"公共子串" | 新增 `copy_check_yaml`（只比对业务字段） |
| `openai` 不在依赖声明里 | 换机器照 README 装完，跑评测 `ModuleNotFoundError` | 写进 `requirements.txt` **和** `pyproject.toml` 的 `dependencies`（不做 optional extra，理由见注释） |

## 四、L2 回放：它证明什么、不证明什么

**这是本版最需要说清边界的东西**，因为理解错了会拿到假安全感：

- ✅ 抓得到：校验器变**严**造成的误报 —— 一份当初合格的录制，现在被判红。
  本项目历史 5 次校验器缺陷**全属此类**（qa 三条污染词表/关键词误报、essay 一条范文自引用、照抄检测对蓝图 100% 误报）。
- ❌ 抓不到：校验器变**松**造成的漏检 —— 要抓这类必须另备「已知坏样本」语料。
- ❌ 两种都抓不到：**模型行为退化**（模板改了、模型不照做了）。那是 L3 的地盘，回放永远替代不了真跑。

这两个方向都用 `--selftest` 注入实验验证过（M1 抓到、M2 按预期抓不到）。

守门用法：

```bash
python replay_eval.py --selftest                         # 验证回放本身好不好使
python replay_eval.py --expect eval_baseline.txt --strict # 清单内任何一份红了就退 1
```

> ⚠️ `eval_runs/` 被 `.gitignore` 排除，**换一台机器 L2 就无米下锅**——此时守门模式
> 直接退码 2，而不是把"零份录制"当成"全部通过"。
> 若要把 L2 接进 CI，得先决定语料能否入库（见第五节）。

## 六、怎么用

```bash
cd PromptTemplate
pip install -e .              # 会把 PyYAML 与 openai 一起装上

# 改完模板，离线自测
python -m pytest -q                            # 91 项
python replay_eval.py --selftest               # 回放本身可用吗
python replay_eval.py -r qa -v                 # 看某个角色的校验器判定
python eval_supervisor.py --self-check         # 督学：范文 + 词表双向审计 + 8 类注入

# 真实评测（要 Key、要花钱）
python eval_planner.py -n 3 --retry 1
python eval_essay.py -n 2
python eval_qa.py -n 2
```

端到端示范（在 `LangChain开发/`）：

```bash
python PromotTemplate.py --dry-run                 # 只组装 Prompt，不调 API
python PromotTemplate.py --cot-table               # 看 CoT 选择表

python PromotTemplate.py --scenario science        # 切回理科场景
python PromotTemplate.py --answer 答偏             # 换学生答案用例（可选值随场景变）
```

## 八、V2.0 之后：补上督学评测（2026-09-29 建，9-30 真跑）

第五节缺口 #2 的三个要点当时都是「知道但没做」。这一轮把它做掉了，两件事：

### 1. 给 `supervisor` 建专属评测

| 做了什么 | 说明 |
|---|---|
| 新增 `eval_supervisor.py` | 4 个用例（`同题` / `physics_浮力` / `chinese_文言虚词` / `low_久未登录`），每个 13 项断言 |
| 重写 `eval_generic.validate_supervisor` | 从「结构校验」升为「结构 + 内容」：模板「输出纪律」那四条规则逐条变成断言 |
| 范文修了两处 | 任务①原来只写「复习笔记」、没写做多少（与新断言冲突，也给模型树坏榜样）；并补上 `{{待复习知识点}}`——该变量一直在模板里，范文却没演示过 |

离线结果（**建好时没调 API**）：`pytest` 91 项全过；`--self-check` 范文 13/13、8 类注入缺陷全部被检出。

### 1b. 真跑一次（2026-09-30，`deepseek-chat`）

```
python eval_supervisor.py -n 2 --retry 1
```

4 个用例 × 2 次 = **8 次调用，首轮全部通过，零重试**（`low_久未登录` 那档 14/14，其余 13/13）。
最难的一档是 `low_久未登录`（入门水平、正确率 30%、已 9 天未登录）——它最容易写成
「你都落后这么多了还不赶紧」。实测的写法是：

```
2. 【数据回顾】你这周已经做了 4 道题，说明你还是愿意动手试试的，这是很好的开始；
   正确率 30%，……另外，你已经 9 天没登录了，我们慢慢找回节奏就好。
3. 【今日任务】① 用 5 分钟看一遍“有理数乘法法则”的符号规则；② 做 2 道小题……
4. 【激励语】小刚，你不需要一下子做很多，今天只把这 2 道题弄明白，就是在往前走了。
5. 【复习提醒】因为你有 9 天没登录了，有理数乘法法则和数轴容易开始遗忘……
```

数据只用输入的 ✓、先讲亮点 ✓、任务 2 个（**没有因落后加量**）且都写了做多少 ✓、
无一句焦虑词 ✓、复习提醒给了依据 ✓。新录制全部归档，守门清单 109 → **117 份**。

### 2. 让它那 6 份录制真正进 L2

此前它们在回放里是「未登记」——因为文件名叫 `rollout_supervisor_…`，而 `discover()` 按首个
下划线切角色，切出来是 `rollout`。现在：剥掉 `rollout_/ablation_/variant_/probe_` 这层运行
种类前缀（`kind` 字段保留用于报告），并登记 supervisor 用例及消融实验用的用例别名。

结果：**5/6 通过**。唯一一份失败是真话——第③条任务「把今天做错的题标一下」没写「做多少」。
守门清单随之从 104 份变为 **109 份**（新增的正是通过的那 5 份）；9-30 真跑后为 **117 份**。

### 3. 顺带修掉的真缺陷

| 缺陷 | 后果 | 修复 |
|---|---|---|
| 污染词表里有「小明」 | 它既是范文里的学生名，也是用例传入的 `{{学生姓名}}` → **每份正常输出**都被判「照抄范文」。旧词表只做单向审计（在范文里吗），没做反向审计（在用例输入里吗） | 移出词表；`self_check` 与 pytest 双双钉住两个方向 |
| 运行种类前缀导致静默跳过 | 报告上只多一句“涉及前缀 rollout”，看上去一片绿 | 见上（剥前缀 + 登记别名） |

### 4. 缺口 #3（语料入库）：已决定不入库（2026-09-29）

`eval_runs/` 依旧不入库，所以 L2 只能在留过录制的机器上跑。三种口径都量过：

| 方案 | 体量 | 代价 |
|---|---|---|
| 只入守门清单那 109 份 | ≈ 470 KB | 换机器能跑 L2；要在 `.gitignore` 里开个白名单目录 |
| 全部 185 份都入 | 1.2 MB | 探索模式也能跑；但含消融/变体实验的中间产物 |
| **不入库（采纳）** | 0 | 新 clone 上 L2 退码 2；要验只能重跑 L3（要 Key、要花钱，且不再是同一份基线快照） |

**决定：不入库。** 理由：①「原始样本不外传」是既有口径（见 `文档索引.md` 第四节）；
② 当前是单人开发、L2 定位为**本地工具**，进 CI 的收益还不存在。
因此 L2 的定位写死为：**本机可用的回归网，不是团队共享的回归网**。
哪天需要多人共享或上 CI，回到这张表重新选口径即可（届时首选「只入 109 份」）。
