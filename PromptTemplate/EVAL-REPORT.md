## 七、答疑角色（qa）补测（2026-09-28）

背景：`qa` 是唯一**既无范文也无评测**的角色（零样本答疑），而且它的模板里
**连“承载提问”的字段都没有**——只能靠调用方另发一条 user 消息，
于是范文的《示例输入》无处对标。本轮补齐三样：

| 补充 | 内容 |
|---|---|
| 模板 | 新增【本次提问】段（承载 `{{学生提问}}` 与知识点链），与 assistant 的【本次批改任务】同构 |
| 范文 | `fewshots/qa.yaml`：数学 1 例 + 语文 1 例；两例的【思路引导】**都不给结论** |
| 评测 | `eval_qa.py`：5 个用例结构断言 + 一条核心断言「引导不喂答案」 |

### 核心断言：引导不喂答案

答疑最容易走形的地方不是格式，而是把「引导」写成了「答案」：
模型一旦兴奋就把结论撂出来，【思路引导】只剩一个标题——那正是答疑与「搜题」的分界。
判法是可程序化的：把该题的结论关键词钉死，它**不得**出现在【思路引导】里。

### 结果

| 用例 | 检查项 | 结果 |
|---|---|---|
| `physics_导热`（与范文不同题） | 8 项 | 2/2 全项通过 |
| `chinese_之字用法`（「其」字，文科） | 9 项 | 2/2 全项通过 |
| `out_of_scope`（超纲问题） | 9 项 | 2/2 全项通过 |

实测三个用例的输出长度 764～1130 字，均带完整 5 模块；
超纲用例会明确说明「超出初中范围」并把话题拉回当前知识点链。

### 本轮发现的三处**校验器自身**错误（都是误报，全在断言侧）

| # | 误报 | 根因 | 修复 |
|---|------|------|------|
| 1 | 把「有理数乘法」判成范文污染 | 它是**输入知识点链自带**的串，正常作答必然出现 | 污染词表必须逐项验证“确实只可能来自范文” |
| 2 | 把「翻折」判成范文污染 | 它是讲解负负得正的**正当概念词**，不是范文独有 | 概念相邻词不能当污染信号；词表收窄到课文锚点 |
| 3 | 把「做完后告诉我你的答案」判成“同类题附了答案” | 只查「答案」二字，不看语义 | 改为只认“真的附上了”的标记与算式结果 |

> 教训：**闸门与校验器的误报同样致命。**
> 过严的检测找不到“正确”与“照抄”的边界时，会直接判所有正确作答不合格。
> 本轮三条误报里两条来自污染词表、一条来自关键词匹配过于字面。

## 八、L2 回放校验（2026-09-28）

### 背景：缺口 #3 的可自动化部分

原来 10 个 `eval_*.py` 把「拿到模型输出」与「校验输出」焊在同一个进程里：
没 Key 就 `sys.exit(2)`，走不到断言。于是**校验器自身**的错误只能靠真跑 + 人眼
发现——而本项目已出过 5 次，全部是误报（qa 三条污染词表/关键词误报、essay 一条
范文自引用误报、照抄检测通用版对 YAML 蓝图 100% 误报）。新增 `replay_eval.py` 把 `eval_runs/` 里的真实输出当“录像”，
直接喂给现成校验器（复用各 `eval_*.py` 自己的 `CASES`，不另写一份用例）。

| 项 | 值 |
|---|---|
| 进入回放的录制 | 118 份 / 27 个用例 |
| 未登记（消融、变体、骨架实验） | 65 份 |
| 文件名无时间戳（`probe_*`） | 2 份 |
| 结果 | **104 份全项通过，14 份有失败项** |
| 需 API Key | 否（已实测：屏蔽 `openai` 模块后，118 份录制的断言结果与本行上方完全一致） |

### 14 份失败全部可解释，无一是新回归

| 组 | 份数 | 解释 |
|---|---|---|
| `assistant` 2026-09-26 批次 | 10 | 分母是模型自编的 `6` 或 `10`。这正是本报告第二节记的旧缺陷；**录制把缺陷现场保留了下来**，现在的断言已经把这条门关上 |
| 首轮未修正版（essay/planner/unit 各 1–2 份） | 4 | `essay_有细节_201111_1`（等级与占比不自洽）、`planner_chinese_201205_1`（净课时 15.5h/12.5h）、`unit_high_212200_1`（作业 0 题）、`unit_noex_212200_1`（H7 出了例题）。**四份都在同目录里存在更晚时间戳的修正版，且修正版全项通过**——与报告里“靠 `--retry 1` 兜底”的记录一致 |

> 观察：这四份恰好就是本报告第五、六、七节记下的那几个真缺陷。回放能把它们
> 逐份指出来，而汇总数字（54/54、116/116…）做不到这一点。

### 自检：L2 抓什么、抓不到什么

`python replay_eval.py --selftest` 向校验器注入两个已知形态的缺陷，只计**注入造成的增量**
（不这么做，语料里历史遗留的失败会把增量淹没，得出假结论）：

| 注入 | 结果 |
|---|---|
| M1 校验器变**严**：把正当概念词「翻折」当成 Few-shot 污染信号（复刻第七节误报 #2） | ✅ 新增 2 份红，被抓住 |
| M2 校验器变**松**：把 assistant 的「置信度」从期望模块里删掉 | ❌ 新增 0 份红，抓不到（符合预期：合格样本在更宽松的断言下照样合格） |

**边界结论（重要）**：

- 抓得到 → 校验器变严（误报）。本项目历史 5 次校验器缺陷**全属此类**（qa 三条、
  essay 一条、照抄检测通用版对 YAML 蓝图 100% 误报）。
- 抓不到 → 校验器变松（漏检）。要抓这类必须另备「已知坏样本」语料。
- 两种都抓不到 → 模型行为退化。那是 L3 的地盘，回放**永远**替代不了真跑。

### 守门模式与它的局限

```bash
python replay_eval.py --write-baseline eval_baseline.txt   # 冻结当前 104 份合格集
python replay_eval.py --expect eval_baseline.txt --strict  # 清单内任何一份红了就退 1
```

- **自指性**：清单是“先把现在能过的挑出来”生成的。它不是正确性证明，而是**当下快照**；
  日后校验器改严时清单必然变红，那一刻要人工判断“是校验器错了还是判定该收紧”，
  而不是默默把清单改小。
- **换机器就空**：`eval_runs/` 被 gitignore，清单里的文件名在别的机器上不存在。
  此时守门模式**直接以退码 2 报错**，而不是把“零份录制”当成“全部通过”——
  空了就绿比红了没人看更糟。因此 L2 目前**进不了 CI**，要进得先解决缺口 #2。

### 顺带修掉的两个真缺陷

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 5 | `superseded` 用**日期**而非「日期+时刻」给一轮评测分组 | 同一天跑多轮时，后一轮的录制会被误当作前一轮重试版的“首轮兄弟”而剔除进不去基线 | 分组键补上时刻；新增 `test_superseded_drops_first_attempt_when_retry_exists` 钉住（当前语料只有 1 个 `_rN` 文件且不触发，属潜在缺陷） |
| 6 | `eval_unit` 的用例内联在 `main()` 里，无法复用 | 回放只能靠复制粘贴用例，而复制粘贴出来的用例一旦与真评测漂移，回放就在验另一套东西 | 提到模块级 `CASES`；`main()` 改用同一份。`--self-check` 输出与改动前逐字一致（已用 `git show HEAD:` 取旧版比对验证） |
| 7 | 语料为空/缺失时，回放会**静默通过**（“没有失败项” ⇒ 退码 0） | 守门脚本最危险的假绿：清单里的文件一份都没跑，却对外宣布成功 | 目录不存在、无可回放录制、清单里有文件缺失——三种情况一律退码 2；另拒给空语料写空清单。`test_gate_refuses_to_pass_when_corpus_missing` 钉住 |
