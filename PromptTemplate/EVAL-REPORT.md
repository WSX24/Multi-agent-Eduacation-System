## 一、本次改动被直接验证的两处

### 1. 新增的「中等」档真的生效（`eval_teacher`）

`中等` 是在本轮补上的第 5 档。此前 `teacher.yaml` 的分支只覆盖 4 档，`中等` 传进去
**不命中任何分支、也不报错**（静默失效）。验证方式是同知识点、只改学生水平，比对输出差异：

```
差分检查：同知识点 / 只改学生水平（验证 branch_rule 是否真生效）
  ✅ 入门 vs 基础   相似度 0.26
  ✅ 基础 vs 中等   相似度 0.34   ← 新增档位与基础档实质不同
  ✅ 中等 vs 进阶   相似度 0.24
  ✅ 进阶 vs 竞赛   相似度 0.33
  ✅ 入门 vs 竞赛   相似度 0.30

  OK H1 5 档输出互不相似(<0.8) []      ← 从「四档」变为 5 档
```

各档正文长度也符合预期梯度（下表每档取最后一份样本，同档多次运行会有波动）：

| 档位 | 例题步骤 | 正文 |
|---|---|---|
| 入门 | 5 步 | 975 字符 |
| 基础 | 4 步 | 1112 字符 |
| **中等** | 3 步 | **1470 字符**（比基础长 32%，与「补 1 道同类变式」一致） |
| 进阶 | 9 步 | 1754 字符 |
| 竞赛 | 2 步 | 1217 字符 |

> 步骤数只是「例题做了多步演示」的低门槛，**不是难度代理**（实测竞赛 2 步 < 入门 5 步）。
> 真正证明分支生效的是上面的两两相似度。

### 2. 满分的分母真的来自输入（`eval_assistant`）

修复前的缺陷：模板要求输出「得分 / 满分」，却从不把满分传进来——分母是模型自己编的；
而旧断言写的是 `sc[0] == sc[1]`（得分 == 自编满分），等于为「模型自己跟自己对得上」盖章。
实测一个 **5 分题**、模型判 `10/10`，旧断言**通过**。

修复后：

```
  ✅ H1 分母 = 传入满分 5（不得自编）   10/10
  ✅ 模块齐全(6)                   10/10
  ✅ 无 LaTeX 记号                 10/10   ← 本轮新增【输出纪律】后仍全过
```

各用例的得分（分母全部来自输入的本题满分 = 5）：

| 用例 | 判定 | 得分 |
|---|---|---|
| 全对 | 对 | (5.0, 5.0) |
| 漏单位 | 部分正确 | (4.0, 5.0) |
| 符号错 | 错 | (0.0, **5.0**) |
| 白卷 | 错 | (0.0, **5.0**) |
| 答非所问 | 错 | (0.0, **5.0**) |
| 字段缺失 | 入口预检拦下 `['学生答案']`，不调用模型 | — |

```
  ✅ 只有「全对」被判为对（判分有分辨力）
```

## 三、复现命令

```bash
cd PromptTemplate

# 依赖：openai（注意：它尚未写进 requirements.txt，见下）
python -c "import openai"

# 免费预检（不调 API，先确认 prompt 组装正常）
python eval_planner.py --dry-run
python eval_teacher.py --self-check
python eval_assistant.py --self-check
python eval_unit.py --self-check
python eval_sprint.py --self-check

# 真实评测（本报告的参数）
python eval_teacher.py   -n 2 --retry 1
python eval_assistant.py -n 2 --retry 1
python eval_planner.py   -n 3 --retry 1
python eval_unit.py      -n 2 --retry 1
python eval_sprint.py    -n 2 --retry 1
```

**API Key 查找顺序**（`eval_planner.load_api_key`）：环境变量 `DEEPSEEK_API_KEY` →
`OPENAI_API_KEY` → `Deepseek_test1` → 读 `<repo>/LangChain开发/.env`。

**换模型**需同时改两个参数：

```bash
python eval_teacher.py --model gpt-4o --base-url https://api.openai.com/v1
```

## 四、已知缺口

| # | 缺口 | 说明 |
|---|---|---|
| 1 | `openai` 不在 `requirements.txt` | 该文件只声明了 `PyYAML>=6.0`；换机器装依赖会缺 openai |
| 2 | 原始样本不入库 | `eval_runs/` 被 gitignore，只有本文件的汇总数字能对比 |
| 3 | 评测需真 API Key、非确定性 | 因此进不了 CI，只能手动跑并人工回填本文件 |
| 4 | `--self-check` 只验 prompt 组装 | 结构层保障；行为层必须真跑 |
| 5 | 履约类断言仍宽松 | 如 `H6 小结为 3 句话` 容忍 2~4 句、`本课目标为一句话` 容忍 ≤2 句，属刻意留的口径模糊余量 |
