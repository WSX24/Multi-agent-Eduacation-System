## 七、答疑角色（qa）补测（2026-09-28）

背景：`qa` 是唯一**既无范文也无评测**的角色（零样本答疑），而且它的模板里
**连“承载提问”的字段都没有**——只能靠调用方另发一条 user 消息，
于是范文的《示例输入》无处对标。本轮补齐三样：

| 补充 | 内容 |
|---|---|
| 模板 | 新增【本次提问】段（承载 `{{学生提问}}` 与知识点链），与 assistant 的【本次批改任务】同构 |
| 范文 | `fewshots/qa.yaml`：数学 1 例 + 语文 1 例；两例的【思路引导】**都不给结论** |
| 评测 | `eval_qa.py`：5 个用例结构断言 + 一条核心断言「引导不喂答案」 |

### 核心断言：引导不喂答案

答疑最容易走形的地方不是格式，而是把「引导」写成了「答案」：
模型一旦兴奋就把结论撂出来，【思路引导】只剩一个标题——那正是答疑与「搜题」的分界。
判法是可程序化的：把该题的结论关键词钉死，它**不得**出现在【思路引导】里。

### 结果

| 用例 | 检查项 | 结果 |
|---|---|---|
| `physics_导热`（与范文不同题） | 8 项 | 2/2 全项通过 |
| `chinese_之字用法`（「其」字，文科） | 9 项 | 2/2 全项通过 |
| `out_of_scope`（超纲问题） | 9 项 | 2/2 全项通过 |

实测三个用例的输出长度 764～1130 字，均带完整 5 模块；
超纲用例会明确说明「超出初中范围」并把话题拉回当前知识点链。

### 本轮发现的三处**校验器自身**错误（都是误报，全在断言侧）

| # | 误报 | 根因 | 修复 |
|---|------|------|------|
| 1 | 把「有理数乘法」判成范文污染 | 它是**输入知识点链自带**的串，正常作答必然出现 | 污染词表必须逐项验证“确实只可能来自范文” |
| 2 | 把「翻折」判成范文污染 | 它是讲解负负得正的**正当概念词**，不是范文独有 | 概念相邻词不能当污染信号；词表收窄到课文锚点 |
| 3 | 把「做完后告诉我你的答案」判成“同类题附了答案” | 只查「答案」二字，不看语义 | 改为只认“真的附上了”的标记与算式结果 |

> 教训：**闸门与校验器的误报同样致命。**
> 过严的检测找不到“正确”与“照抄”的边界时，会直接判所有正确作答不合格。
> 本轮三条误报里两条来自污染词表、一条来自关键词匹配过于字面。

## 八、L2 回放校验（2026-09-28）

### 背景：缺口 #3 的可自动化部分

原来 10 个 `eval_*.py` 把「拿到模型输出」与「校验输出」焊在同一个进程里：
没 Key 就 `sys.exit(2)`，走不到断言。于是**校验器自身**的错误只能靠真跑 + 人眼
发现——而本项目已出过 5 次，全部是误报（qa 三条污染词表/关键词误报、essay 一条
范文自引用误报、照抄检测通用版对 YAML 蓝图 100% 误报）。新增 `replay_eval.py` 把 `eval_runs/` 里的真实输出当“录像”，
直接喂给现成校验器（复用各 `eval_*.py` 自己的 `CASES`，不另写一份用例）。

| 项 | 值 |
|---|---|
| 进入回放的录制 | 118 份 / 27 个用例 |
| 未登记（消融、变体、骨架实验） | 65 份 |
| 文件名无时间戳（`probe_*`） | 2 份 |
| 结果 | **104 份全项通过，14 份有失败项** |
| 需 API Key | 否（已实测：屏蔽 `openai` 模块后，118 份录制的断言结果与本行上方完全一致） |

### 14 份失败全部可解释，无一是新回归

| 组 | 份数 | 解释 |
|---|---|---|
| `assistant` 2026-09-26 批次 | 10 | 分母是模型自编的 `6` 或 `10`。这正是本报告第二节记的旧缺陷；**录制把缺陷现场保留了下来**，现在的断言已经把这条门关上 |
| 首轮未修正版（essay/planner/unit 各 1–2 份） | 4 | `essay_有细节_201111_1`（等级与占比不自洽）、`planner_chinese_201205_1`（净课时 15.5h/12.5h）、`unit_high_212200_1`（作业 0 题）、`unit_noex_212200_1`（H7 出了例题）。**四份都在同目录里存在更晚时间戳的修正版，且修正版全项通过**——与报告里“靠 `--retry 1` 兜底”的记录一致 |

> 观察：这四份恰好就是本报告第五、六、七节记下的那几个真缺陷。回放能把它们
> 逐份指出来，而汇总数字（54/54、116/116…）做不到这一点。

### 自检：L2 抓什么、抓不到什么

`python replay_eval.py --selftest` 向校验器注入两个已知形态的缺陷，只计**注入造成的增量**
（不这么做，语料里历史遗留的失败会把增量淹没，得出假结论）：

| 注入 | 结果 |
|---|---|
| M1 校验器变**严**：把正当概念词「翻折」当成 Few-shot 污染信号（复刻第七节误报 #2） | ✅ 新增 2 份红，被抓住 |
| M2 校验器变**松**：把 assistant 的「置信度」从期望模块里删掉 | ❌ 新增 0 份红，抓不到（符合预期：合格样本在更宽松的断言下照样合格） |

**边界结论（重要）**：

- 抓得到 → 校验器变严（误报）。本项目历史 5 次校验器缺陷**全属此类**（qa 三条、
  essay 一条、照抄检测通用版对 YAML 蓝图 100% 误报）。
- 抓不到 → 校验器变松（漏检）。要抓这类必须另备「已知坏样本」语料。
- 两种都抓不到 → 模型行为退化。那是 L3 的地盘，回放**永远**替代不了真跑。

### 守门模式与它的局限

```bash
python replay_eval.py --write-baseline eval_baseline.txt   # 冻结当前 104 份合格集
python replay_eval.py --expect eval_baseline.txt --strict  # 清单内任何一份红了就退 1
```

- **自指性**：清单是“先把现在能过的挑出来”生成的。它不是正确性证明，而是**当下快照**；
  日后校验器改严时清单必然变红，那一刻要人工判断“是校验器错了还是判定该收紧”，
  而不是默默把清单改小。
- **换机器就空**：`eval_runs/` 被 gitignore，清单里的文件名在别的机器上不存在。
  此时守门模式**直接以退码 2 报错**，而不是把“零份录制”当成“全部通过”——
  空了就绿比红了没人看更糟。因此 L2 目前**进不了 CI**，要进得先解决缺口 #2。

### 顺带修掉的两个真缺陷

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 5 | `superseded` 用**日期**而非「日期+时刻」给一轮评测分组 | 同一天跑多轮时，后一轮的录制会被误当作前一轮重试版的“首轮兄弟”而剔除进不去基线 | 分组键补上时刻；新增 `test_superseded_drops_first_attempt_when_retry_exists` 钉住（当前语料只有 1 个 `_rN` 文件且不触发，属潜在缺陷） |
| 6 | `eval_unit` 的用例内联在 `main()` 里，无法复用 | 回放只能靠复制粘贴用例，而复制粘贴出来的用例一旦与真评测漂移，回放就在验另一套东西 | 提到模块级 `CASES`；`main()` 改用同一份。`--self-check` 输出与改动前逐字一致（已用 `git show HEAD:` 取旧版比对验证） |
| 7 | 语料为空/缺失时，回放会**静默通过**（“没有失败项” ⇒ 退码 0） | 守门脚本最危险的假绿：清单里的文件一份都没跑，却对外宣布成功 | 目录不存在、无可回放录制、清单里有文件缺失——三种情况一律退码 2；另拒给空语料写空清单。`test_gate_refuses_to_pass_when_corpus_missing` 钉住 |

```bash
python replay_eval.py --selftest            # 自检：M1 抓到 / M2 抓不到
```

## 九、督学角色（supervisor）补建评测（2026-09-29）

### 背景：8 个角色里唯一一处「模板写了规则、却没人查」

`supervisor` 在端到端流程里真跑（阶段 5），却是唯一**没有专属评测**的角色：此前只有
`make_section_validator` 生成的结构校验（5 个模块齐不齐、顺序、有无 LaTeX），而模板最
要紧的四条约束全在「输出纪律」那一段，**全是内容，一条都没有程序化断言**：

```

2. 【任务必须可完成】1-3 个，且写明「做什么 + 做多少」
```

共 **13 项断言**，上表四条规则逐条落地：

| 模板规则 | 断言 | 判定方式 |
|---|---|---|
| 数据只用输入的 | 数据回顾只用输入数据 | 【数据回顾】里的数字必须能在输入的 `{{学习数据}}` 里找到 |

| 不制造焦虑 | 不制造焦虑 | 禁词：倒计时 / 落后 / 惩罚 / 来不及 / 必须马上… |
| 复习提醒要有依据 | 复习提醒说明依据 + 引用待复习知识点 | 要说出为什么现在提醒，且引用输入的 `{{待复习知识点}}` |

## 十、材料题示范作答（teacher_material）建角色 + 建评测（2026-10-01）

背景：V2.0-说明 缺口 #1。阶段 3B 原先借 `teacher` 渲染，而 `teacher` 的输出契约是

## 十一、作文构思（teacher_outline）建角色 + 建评测（2026-10-01，承接第十节）

背景：与第十节同源——阶段 4A 原先借 `teacher` 渲染，真跑输出 1180 字符全是
【本课目标】【知识讲解】【典型例题】（还带 `need_example=false` 留下的空壳
「本节课不提供例题」）、【易错提醒】【小结】，外加「先问一句：……不能。」「通俗例子：……」
这种讲解口吻。**内容其实不差**（审题/立意/提纲/素材都在），错的是外壳。

第十节把材料题做成了「作答体」，这一节把作文构思做成「构思体」——两者都是「非讲课」角色，
但契约不同：材料题交结论+依据，构思交中心句+提纲+素材，不能互相顶替。

### 11.1 做了什么

| 项 | 内容 |
|---|---|
| 新角色 | `templates/teacher_outline.yaml`（v1.0）：【审题】/【立意】/【提纲】/【素材】/【首尾】，并给每个模块固定起头词（`反例：` `中心句：` `支撑：` `第N段（作用）：` `素材N：… —— 它证明：` `开头：` `结尾：`），使「写的是不是构思」可程序化判定 |
| 范文 | `fewshots/teacher_outline.yaml`：**按文体**给两例（记叙文用起承转合 / 议论文用总分总）。只给一例会让模型把提纲一律写成起承转合 |
| 校验器 | `eval_generic.validate_outline`（17 项断言）：核心是**立意不骑墙**、**提纲每段≤120字**（防写成段落实文）、**提纲 3-5 段**、**素材必须说明它证明什么** |
| 评测器 | `eval_outline.py`：2 用例（记叙文《这也是课堂》/ 议论文《小议『捷径』》）；`--self-check` 含 8 类注入 |
| 闸门 | 阶段 4A 改为 `style="gate"`（此前 `one_shot` 直出） |
| L2 登记 | `replay_eval.py` 登记 `outline` 角色，`outline_<用例>_…` 不再被静默跳过 |

### 11.2 结果（`deepseek-chat`）

### 11.3 本轮踩到并修掉的两个自检缺陷（都在测试侧）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 注入用例把「第5段/第6段」接在**全文末尾** | 那是【首尾】模块，不算提纲段，于是「提纲 3-5 段」这条断言没被触发——注入样本本身就无效。已改为插在【提纲】内部 |
| 2 | 范文输入的字段标签是「题目与要求」，解析器只认「题目」 | 离线自检直接 KeyError。已改为只认已知标签并做名称映射 |

这两条与第十节里 `parse_example` 的截断问题是同一类：**自检工具的输入解析，比断言本身更容易出错**。

### 11.5 边界

- **仍是 2 用例 × 2 次**：采样少，谈不了稳定性。
- **「提纲每段≤120字」是个代用指标**：它抓的是「把提纲写成段落实文」这个形态，
  不是精确的「有没有写成全文」。真要判全文，得比对字数与文体特征，成本远超收益。
- **素材的「它证明」是形式断言**：写了「它证明」不等于证明得对，后者仍需人看或 L3。
- 与第十节共同的边界：L2 语料不入库（缺口 #3），换机器 L2 无米下锅。

## 十二、把两处「形式断言」做成实质断言，并用 `-n 5` 采样验证（2026-10-01）

第十一节留了两个诚实的边界：

1. 「提纲每段 ≤120 字」只是**代用指标**，抓的是形态，不是「有没有写成全文」；
2. 素材的「它证明」是**形式断言**——写了不等于证明得对。

这一节把这两条做实，然后用 `-n 5`（每用例 5 次）采样去检验：新断言在真实模型下站不站得住。

### 12.1 提纲：从「卡字数」改成「三条形态判据」

| 判据 | 抓什么 |
|---|---|
| 句数 ≤ 2 | 提纲是「一句话说明这一段干什么」；3 句以上基本就是叙事段落 |
| 字数 ≤ 120 | 兜底，防逗号长句 |
| ~~不得含「」引文~~ | **已删——它是假红**（见 12.3） |

### 12.2 素材：从「写了它证明」改成「与提纲咬合」

原来只查「有没有写『它证明』」，现在四条一起看：

| 判据 | 抓什么 |
|---|---|
| 每条素材标注「（用在第M段）」 | 素材不许悬空 |
| M 必须是提纲里真实存在的段号 | 段号编造 / 提纲改了素材没跟 |
| **标了「← 重点」的段必须有素材** | 立了重点段却空着（最常见的结构漏） |
| 「它证明」不得与中心句高度相似（difflib ratio ≥ 0.7） | 把中心句抄一遍当证明 |
| 「它证明」≥ 8 字；量长度前先剔掉「（用在第M段）」 | 敷衍成「它证明：很好」 |
| 素材条目 ≥ 20 字 | 空壳素材 |

断言从 17 项升到 **22 项**。注意目标仍是**可判定的形态**：写了「它证明」且与提纲咬合 ≠ 证明得对，
后者是语义问题，归人看或 L3（这条边界没变）。

### 12.3 `-n 5` 采样暴露的两处假红（都是我的判据太严）

```
python eval_outline.py -n 5 --retry 1
```

**假红 ①「提纲不得含「」」**：拦下 2/10 份，原句是

```
第4段（合）：……我明白了「不糊弄」是什么意思，回扣中心句。
第1段（总）：引出「捷径」话题，亮出中心句。
```

「」里包的是**题眼/主题词**，不是对白；回投后模型也删不掉（题眼就长那样）——
典型的「过严的闸门回投也修不好」。判据已删，两句当回归样本钉进测试。

**假红 ②「无讲解口吻」误伤引号里的修辞**：拦下 3/10 份，原句是作文**开头句**：

```
开头：「人人都想找捷径，但很少有人先问一句：我有没有走捷径的资格。」
```

而旧版 4A 真正的讲课腔是**不带引号**的（「先问一句：拿到《这也是课堂》，能不能……」）。
判据改为「先剥掉「」引文再扫」，真假两例仍能分清（有测试钉住两个方向）。

**顺带修掉一处提示词冲突**：`立意有中心句与支撑` 首轮失败 2~3 次，原因是「中等档」分支
要求「在『中心句：』后补一句为什么不会被反例推翻」，模型就把「支撑：」省掉了。已在分支里
写明「中心句与支撑两个都要写」，并把补充句固定成「抗反例：」起头。

### 12.4 修完之后的 `-n 5` 结果

| 轮次 | 首轮即通过 | 首轮失败项分布 |
|---|---|---|
| 修之前 | **4/10** | 无讲解口吻 3、立意有中心句与支撑 2、重点段有素材支撑 1、无 Few-shot 题目污染 1 |
| 修之后 | **9/10** | 重点段有素材支撑 1 |

10/10 最终全项通过（23 项）。唯一剩下的首轮失败是**真问题**：模型把总起段标了「← 重点」
却把素材都给了后面两段；回投后修正。

材料题（`eval_material.py -n 5 --retry 1`）：**首轮 8/10**，10/10 最终通过，
首轮失败项全是「依据引用了材料原文」——真问题，闸门拦下后回投修正。

**「无 Few-shot 题目污染」那次也是真命中**：议论文用例里模型写了

```
素材3：有人把「三分钟看完名著」当读过原著 —— 它证明：把过程压成结论，读者得不到体会。
```

范文示例里是「有人把『三分钟看完《西游记》』当成读过原著」——素材被搬了过来，判为串味正确。

### 12.5 顺带改进：每次尝试都落盘

原先评测器「重试成功才落盘」，于是**首轮被闸门拦下的原文不留痕**——只看最终结果会把
「闸门拦下了什么」这件事吞掉。现改为每次尝试都写文件：首轮不带后缀，重试带 `_r1/_r2`。

- 首轮那份按设计就是不合格的，L2 的 `superseded()` 会把它排除在基线之外（已核验：0 冲突）；
- 但要`-v`看时它就在那儿，闸门的每次干预都可复核。

### 12.6 L2 守门清单：127 → **173 份**

```
python replay_eval.py --expect eval_baseline.txt --strict  → 173 份，173 通过，退码 0
```

体量变大是因为两处评测都跑了 `-n 5`（含重试版），比之前的 2 次采样厚得多。

### 12.7 边界（这一节之后仍然成立）

- **「证明得对」仍不可判定**：咬合与长度都只是形态；真正的语义正确要人看或 L3。
- **10 次采样仍是小样本**：它足够抓出 20%~30% 级别的漂移（这次两次都抓到了），
  但不足以谈「通过率 90%」这类精确数字。
- **假红的教训是一致的**：两次都发生在「我为了抓 X 而写的一条形态判据」上，
  且都是模型完全正当的写法。判据越贴近「写法」，越容易误伤——优先挑「结构」而非「措辞」。

## 十三、补上两个新角色的「档位差分」评测，并扩大用例面（2026-10-01）

第十二节末尾列的两条覆盖度边界，这一节做掉：

1. `teacher_material` / `teacher_outline` 只真跑过各自默认的那一档（基础 / 中等），
   其余四档**只有组装层断言**——而 `teacher` 当年正是栽在「取值域里有『中等』、
   分支里却没有」这种缺口上；
2. 用例面窄：材料题 2 例、构思 2 例，换个学科/命题方式会不会走形，没验过。

### 13.1 新增 `eval_levels.py`（五档差分）

同一道题**只改 `{{学生水平}}`**，看五档输出是否真的分层——这是 `eval_teacher` 的口径，
现在推广到两个新角色：

| 断言 | 内容 |
|---|---|
| L1 档位特征 | 只锚定**模板逐字规定的起头词**：中等档的 `抗反例：`、竞赛档的`备选`、进阶档的`细节`、材料题中等档在【回扣设问】里点明的`动词` |
| L2 档位不越界 | 入门档不得出现中等档的 `抗反例` |
| L3 差分 | 五档**两两相似度 < 0.8**（4 个相邻对 + 1 个首尾对，从档位元组派生，不手写——手写会漏档） |
| L4 结构 | 每档仍要过该角色自己的结构校验器：**跑分档不能以破坏契约为代价** |

为什么断言优先用「模板写死的起头词」而不是泛泛关键词：本项目踩过「关键词判据误判」——
模型是**示范**某个档位，不是**标注**它（`teacher` 那次的教训写在第 68 行注释里）。

### 13.2 真跑结果（`deepseek-chat`，每档 1 次）

```
python eval_levels.py --role outline  -n 1 --retry 1
python eval_levels.py --role material -n 1 --retry 1
```

| 角色 | 入门 | 基础 | 中等 | 进阶 | 竞赛 | 五档两两相似度 |
|---|---|---|---|---|---|---|
| `teacher_outline` | 26/26 | 23/23 | 24/24 | 24/24 | 24/24 | 0.32 ~ 0.47 ✅ |
| `teacher_material` | 14/14 | 14/14 | 15/15（重试 1 次） | 14/14 | 15/15 | 0.32 ~ 0.55 ✅ |

正文长度也随档位单调变化（构思：481 → 645 → 717 → 709 → 862 字符），说明档位真的改了产出。

### 13.3 差分抓出的一处真冲突：模板说 1 条，断言要 2 条

`eval_levels` 第一次跑构思就红了：

```
入门   24/25（重试 1 次）
      ✗ 素材至少 2 条  实际 1 条
```

原因是两处打架：模板「条件分支指令」里入门档明写**「素材只给 1 个」**（简化入门学生的负担），
而 `validate_outline` 无条件要求「素材至少 2 条」。

**判定：以模板声明的契约为准，断言按档位放行**——条数下限改为档位相关
（入门 1 条、其余 2 条），并在档位断言里补上「入门档·素材为 1 条」这一条，
把入门档的行为**双向**钉住（既不多也不少）。

这类冲突只有「跨档位真跑」才暴露得出来：单档评测永远看不到两条规则在某一档上互斥。

### 13.4 用例面：各加一例，换学科 / 换命题方式

| 评测 | 新增用例 | 换的是什么 |
|---|---|---|
| `eval_material` | `历史_秦汉集权`（史料 + 「结合材料与所学」） | 换学科（历史）；且这是**第一个需要补背景**的用例——`source_analysis` 第 4 步正是为「结合所学」写的，此前两例都是「根据材料」，从没验过这一支 |
| `eval_outline` | `材料作文_自拟题目`（给材料 + 自拟题目） | 换命题方式：没有现成题眼可抓，审题难度与「抓题眼」不是一回事 |

真跑（各 `-n 2 --retry 1`）：

```
eval_material → 3 用例 × 2 = 6 次，全部 14/14；首轮 5/6（唯一首轮失败是「依据引用了材料原文」，真问题，回投修正）
eval_outline  → 3 用例 × 2 = 6 次，全部 23/23；首轮 6/6，零重试
```

附带证据：新用例与污染词表**无冲突**（双向审计测试会自动遍历所有用例，新增用例同样受检）。
