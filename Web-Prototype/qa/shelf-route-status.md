# 附：480p 可行版「一本书的光」（2026-09-26，用户选方案 3）

## 为什么要换题材，而不是换提示词

失败的不是措辞，是**题材的空间频率**。480p + `ltx-2.3` 守不住「一排书脊」这种
细密高频结构——5 秒内画面漂成另一张画（边缘相关 0.095，未分类彩色 3% → 15%）。
480p 能做好的东西是：**大形状、强对比、发光体、慢运镜、低结构密度**。

所以把镜头改成「一本书的光」，保住用户的三个节拍：

| 原要求 | 480p 版的做法 |
| --- | --- |
| 一个书架 | **一本摊开的大书**（两块大弧面 + 一条中缝，纯大形状，无书脊） |
| 知识化作一道道光芒 | **一大团柔和的光从书页升起**（细如发丝的光在 480p 下必然糊） |
| 汇聚到我们的智能体 | 光缓慢朝右上方那颗暗的**核心**漂去 |
| 一镜到底 | 极缓推近 + 无切；光单一连续地升起并移动 |

背景纯净、无装饰——**模型漂移在这种画面上看不出来**，这既是妥协也是策略。

## 验收（简单画面不能用边缘相关）

画面 92% 是平坦亮区，边缘能量太稀疏，**边缘相关在这个画面上不可靠**
（t=0 只有 0.333）。改用**固定区域的亮度与对比度**，以及紫色的位置：

| t | 书所在固定区 均亮/std | 核心所在固定区 均亮/std | 紫% |
| --- | --- | --- | --- |

| 1.2 | 226.7 / 26.4 | 213.1 / 59.1 | 0.41 |
| 2.5 | 236.9 / **12.8** | 209.1 / 58.7 | 0.85 |
| 3.8 | 237.4 / 21.8 | 198.7 / 59.0 | **1.26** |
| 4.9 | 231.7 / 38.2 | 184.1 / 73.6 | 0.68 |

结论：

- **构图守住了**：书始终在画面的下部带内，核心始终在右上；两者都没有漂走
- **光做出来了**：紫色在 t≈2.5–3.8 出现并达到峰值，位置在书的上方偏右，
  t=4.9 时移到核心附近；核心区的对比度从 56 升到 74（光到了它身上）
- **中段有一次冲亮**：书区对比度 38.5 → 12.8 → 38.2，读作一团光扫过书页。
  它符合「知识化作光」，但不是被要求的效果 —— 若要书页始终清晰，
  提示词要改成「光从书页上方升起、不覆盖书页」

## 仍未满足的

均亮 226–235、紫 ≤3.55%、褐色 ≤1.82%、过曝 ≤0.05%。

## 5. 集成时抓到的四个问题（都已修）

1. **`python -m http.server` 不支持 HTTP Range** → 视频 `seekable` 变成 `[0.00..0.00]`，

4. **`mask-image` 在 `--disable-gpu` 的无头环境里整层画不出来**（去掉遮罩影片立刻出现）。

**底片效果**（紧贴字形一圈 vs 远处同高背景）：

| p | 紧贴字形一圈 | 远处同高 | 抬升 | 黑字对比度 |
| --- | --- | --- | --- | --- |
| 0.00 | (198,195,193) | (170,166,165) | **+28.4** | **11.1:1** |
| 0.40 | (198,195,192) | (172,166,164) | **+27.6** | ~11:1 |
| 1.00 | (187,189,190) | (163,159,159) | **+28.3** | ~10:1 |

底片强度由 `inset` 与渐变的 alpha 控制，想更明显只改那一个 `.34`。

## 测量方法的两点记录（避免下次重复踩）

1. **不能取「全画面最暗的 0.5%」当字形核心** —— 影片自身有大量深灰结构，
   会把这批像素全占掉，量出来是影片的暗部而不是文字。
   必须「藏视频那张定位文字像素 → 有视频那张读同一位置」。
2. **不能用一个大的外扩框平均底片** —— 底片是径向渐变，边缘淡出，
   大框会把抬升平均掉，得出「底片没生效」的假结论（p=0.00 就误判过一次）。
   要取紧贴字形的一圈（膨胀 3–18px）。

## 顺带

- `tools/serve.py` 加了 `Cache-Control: no-store`：改了 CSS 却看到旧样式，
  会让人以为是代码没生效（本项目踩过一次）。开发/验收服务器不该缓存。
- 蓝方案的数字留档：`#0078D4` 在影片上 1.83:1、`#17479a` 3.21:1。
  想切回蓝只改 `--say-ink` 一行。

# 附十：修好「双击打开不动」+ 按钮透明（2026-09-26）

用户报：`动画怎么不放了？按钮我要透明的`。

## 1. 动画不动 —— 根因是 file:// 拒载 ESM

用户是**双击 HTML（file://）**打开的，而 `file://` 下有两件事会被浏览器直接拦掉，
首屏两个都踩中：

| # | 触发点 | 后果 |
| --- | --- | --- |
| 1 | `landing.html` 里 `<script type="module" src="js/film-runtime.js">` | 模块要求 CORS 同源，**本地文件算不透明源**，脚本**根本不执行** → `data-film` 不被设置 → 画面静止 |
| 2 | `js/film-runtime.js` 的 `fetch('build/timeline.json')` | 同样是 CORS，`file://` 下必失败 |

**决定性对照**（同一份代码）：

| 打开方式 | `data-film` | 结果 |
| --- | --- | --- |
| `file://` 双击 | **未设置** | 不动 |
| `tools/serve.py` 服务器 | `media` | 正常 |

### 修法

新增 `tools/build_classic.py`，把 ESM 运行时打成**经典脚本**：

| 产物 | 内容 |
| --- | --- |
| `js/film-runtime.classic.js` | 内联 vendor（去掉 `export`）+ runtime（`import` 换成从 `window.OilMotionVendor` 取）；vendor 与 runtime **各占一个 IIFE 作用域** |
| `build/timeline.js` | `window.OIL_TIMELINE = {…}` —— 时间轴以脚本注入，绕开 fetch |

`landing.html` 改成三个经典脚本，**顺序不能换**：
`build/timeline.js` → `js/film-runtime.classic.js` → `js/landing.js`。
`js/film-runtime.js` 仍是唯一事实源，改成优先读 `window.OIL_TIMELINE`、没有才 fetch。

**为什么两个作用域**：vendor 和 runtime 都有 `clamp` / `wrap` 这类短名顶层声明，
放进同一个作用域会重名 —— 实际撞过一次 `createFrameAnimator`。

**改了源文件要重跑**：`python tools/build_classic.py`（`--check` 只检查是否过期）。

### 验证（两路都过）

| 路径 | 结果 |
| --- | --- |
| `file://` 双击 | `data-film=media`、`frame=120`、`want=5.0000 have=5.0000` |
| `tools/serve.py` | `data-film=media`、`want=5.0000 have=5.0000` |

## 2. 按钮改成透明

`css/base.css` 的 `.btn-sky`：`background: transparent` + `border-color: currentColor`
（全透明底在影片上会没有边界、看不出是按钮，所以留一圈 `currentColor` 描边；
不想要就删那一行）。hover/active 用半透明白提亮。

**透明性实测**（藏视频那张定位「页面底色」像素，再读有视频那张同位置）：

```
藏视频时这些像素均值 (253,253,246)  ← 页面底色，说明底是透的
有视频时这些像素均值 (159,171,178)  ← 是影片内容
标准差 43.5（0 = 一块纯色 = 不透明）
```

即影片真的透过按钮显示出来，不是一块纯色盖上去。

`--sky / --sky-hover / --sky-active` 三个 token 现在暂时没人用了，留着方便切回。

对照图 `qa/copy-sheet-final.png`。

# 附十二：「Teaching Platform」加刚好包裹的亮片（2026-09-26）

用户指令：`Teaching Platform加个小范围高透明度的亮片，只需要刚好包裹住就行`。

## 做法

`.say-item .l2` 原来是 `display: flex`，**宽度撑满整栏** —— 直接加底片会变成一整条。
改成 `display: inline-flex; width: fit-content`，盒子才收紧到文字宽度。

亮片挂在 `.l2::before`：

```css
.say-item[data-say="brand"] .l2 { padding: 3px 12px; margin-left: -12px; border-radius: 9px; }
.say-item[data-say="brand"] .l2::before { inset: 3px 0 -3px 0; background: var(--plate); }
```

两个细节：

- **`margin-left: -12px` 抵消横向 padding**：文字左缘仍与上面的 `AI` 对齐（实测字形左缘
  x=57，与 `AI` 一致），底片只是左右各探出一点 —— 这就是「包裹」的观感。
- **`inset: 3px 0 -3px 0` 而不是 `inset: 0`**：行高 1.1 时字形在行盒里偏下，
  贴合会得到「上 8 下 2」的偏心包裹（字形看着像掉出底片）。整体下移 3px 后是「上 5 下 5」。

透明度抽成一个共用 token，按钮与字标用同一个值，避免两处魔数：

```css
--plate: rgba(255, 255, 255, .5);   /* css/tokens.css */
```

## 实测（`?hide=text` 做差，把亮片与字形精确分离）

```
亮片 bbox   x 44-397   y 479-526    宽 354  高 48
字形        x 57-383   y 484-521    宽 327  高 38
包裹余量    左 13   右 14   上 5   下 5  px
```

- 亮片占画面宽 **25%** —— 不是撑满一栏。
- 亮片上方 90px 内亮片像素 **0** —— 只包 `Teaching Platform`，没包到 `AI`。
- 有效不透明度 **0.474 → 53% 透明**，与 token 的 `.5` 一致。
- 亮片上的字对比度约 **9.9:1**。

## 第四个测量坑（记下来）

**同一页面的两张截图，影片帧可能不一致。** 截图与视频 seek 是并发的，
偶尔一张停在 poster/前帧，做差就会「差异铺满全屏」，亮片定位整片失效
（实际发生过一次）。做法：做差前先**校验一块无文字区**（右下角）两图是否一致，
不一致就重截。重试一次就过了。

对照图 `qa/copy-sheet-plate2.png`（整幅 + 字标亮片放大 + 按钮亮片放大）。
