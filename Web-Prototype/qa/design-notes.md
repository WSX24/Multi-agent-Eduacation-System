# 镜头设计（2026-09-26 重做）

用户反馈两条：「纸张没有铺满浏览器」「全是乱七八糟的线条」，以及
「你要设计出到底是什么样的镜头」。两条都成立，第二条尤其 —— 在此之前
**镜头从来没有被真正设计过**：我从头到尾看不见图，靠 108×26 的字符图判构图，
那个分辨率下一条 4px 宽的线会整条消失（每格 15px，线被平均掉）。
所以「乱」不是执行失误，是必然产物。

## 0. 先造眼睛

`tools/preview_composition.py`：不再经过截图，直接读 `build/line-runtime-data.js`，
用与运行时同一个相机变换把采样点投到屏幕，把**中心线**光栅化成掩模，
再按字符网格取「格内有没有墨」——所以线不会消失。

它同时报三个量：`墨格占比`、`行内最多穿过几格`、`连通块数`。
「乱」在这三个量上是有信号的：重做前 p=1.00 是 18.1% / 61 格 / 1 块，
重做后是 14.8% / 50 格 / 2 块，而且字符图上一眼能读出「上方一条曲线 + 下方一本书」。

## 1. 「纸张没有铺满」的真实原因（三个，都不是纸的问题）

| 原因 | 实测证据 | 处置 |
| --- | --- | --- |
| **纤维层被纸板整层盖住** | `paper--macro` 不透明且在 DOM 里排在纤维**之后**（= 在上）；纤维只在 s>1.24 淡出后才露出来，而最大缩放只有 1.06 —— 等于从来没露过。块内标准差只有 **1.03**，纸就是一块平色 | 调换顺序：纸板在下、纤维在上 |
| **单向压暗的纤维** | 纤维峰值不透明度 0.13 就把整幅均亮从 241 压到 **229** | 改成**双向颗粒**：暗颗粒用接近纸色的 (196,197,202)、亮颗粒用白，幅度对称 → 均值不动 |
| **视差光层 + 纸板的大尺度褶皱** | 光层随相机偏移造成斜向明暗带；纸板的 p1..p95 跨 21 级，被铺到画面上就是可见的明暗块。四角均亮相差 **22 级** | 机位固定后视差光层没有意义，删掉；纸板曲线从「提亮」改为**压缩**（236..247，11 级），保留褶皱形状但变成很淡的起伏 |

修完之后（纯纸帧 `?p=0&chrome=0` 实测）：

```
整幅均亮 237.8   块均亮极差 8.4（目标 <12）   块内标准差 中位 4.42（目标 2.5–5）
完全平的块 0 个   四边 8px 条带均匀
```

**一条可复用的经验**：在亮底上做任何叠加（可读性垫层、纸的颗粒），
都会压暗而不是提亮 —— 因为底色已经接近白，能加的空间只有几级，能减的有 200 级。
所以要么用底色本身做垫层，要么把叠加做成双向对称的。

## 2. 镜头设计

### 2.1 固定构图（本次最关键的一条）

- **锚点锁在纸心**（`anchor.bias = 1.0`）。此前锚点贴着笔尖走（0.25），
  构图会随笔尖漂到哪儿算哪儿 —— p=0.62 时笔尖走到右墙，画面里就只剩一条竖线。
  现在构图是**设计出来的**：设计画布 = 视口在 s=1 时的世界区域
  （x 400..2000 / y 475..1375），所有笔画都设计在这个框里。
- **缩放只做 0.88 → 1.06 的居中缓推**（约 20%）。此前的 0.64 → 1.6 是
  3.5 倍推轨，构图在设计时无法预估，只能靠事后调参。

### 2.2 等宽笔画（第二关键）

变宽度会让「沿已有线回描」留下可见的增粗，于是每一笔都必须各走各的、
不能互相借道 —— 那样画多个形状必然织成网。上一版 77 段就是这么变成一团乱线的。
等宽之后回描完全不可见，一笔画才能画出**结构**。

代价：失去手写的粗细变化。收益：可以画有结构的东西。

### 2.3 画什么

```
摊开的书（大、居中，占 87% 幅宽）
  ├ 左下缘 → 左外缘 → 左上缘 → 书脊 → 右下缘 → 右外缘 → 右上缘
  └ 右页三行文字线：严格平行于页面顶边（斜率 0.221），
     三个竖跳等长 50，入口与出口的跳也等长 —— 读成"有字的纸"而不是交叉阴影
从书脊升起的一条遗忘曲线（占满上方空白）
收笔小回环
```

笔画全部落在**两条水平带**里（书上带 y 965..1330，曲线上带 y 640..965），
互不穿插。总长 7.3k 单位、19 段、只有书这一个闭合形状。

### 2.4 进度按「可见长度」分配

回描旅行不产生新墨，但占弧长；按总弧长分配进度会让人滚了一大段而画面没动静。
构建期算出每个采样点是否在回描（与更早采样点距离小于笔宽 0.8 倍），
回描段在进度分配里只占 0.12 的权重。实测回描占比 12.4%。

`sampleAt` 这张表把两件事一起折进去交给运行时：
**屏幕速度补偿**（`d已画/dp ∝ 1/缩放`）与**可见长度加权**。

### 2.5 其他

- 行程 1000vh → **400vh**（3 屏）。路径总长从 28.4k 降到 7.3k，行程不跟着缩会爬。
- 采样 520 → **900**（路径短了，可以加密，曲线段更平滑）。
- 紫色起点 0.66 → **0.72**（正好落在曲线段，河道从书里升起）。
- 底稿默认仍为 `off`：整幅构图提前可见会破坏落笔的顺序感。
