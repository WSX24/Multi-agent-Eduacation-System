# 几何门的校准记录

工具：`tools/verify_geometry.py`。目的与动机见 `qa/integration.md` §7 ——
亮纸 / p95 / 过曝 / 紫色这四条门限量的是**色调**，看不见「画在错的位置」。

## 1. 原理

把 `build/line-runtime-data.js` 里的采样点按**与运行时同一个相机变换**
（`scaleAt` / `drawnAt` / `tipAt` / 锚点偏置）投到屏幕坐标，用与
`js/line-runtime.js` 的 `ribbon()` 同构的多边形（左偏移 + 末端帽 + 右偏移 +
起端帽）光栅化成「理论上墨应该在哪」的掩模，再与截图里实际是墨的像素求：

- **交并比 IoU**
- **墨面积比**（实测 / 理论）
- **重心偏差**（绝对值 + 占理论包围盒对角线的比例）

## 2. 阈值扫描（为什么阈值取 205 而不是 160）

第一版取 160（纸 235–245、格线约 231、墨约 42–70，看起来分得很开）。
结果正确几何在 p=1.00 上被判死：IoU 0.51、面积比 0.57、重心偏 97px。

原因：**s=0.5 时笔画只有约 2px 宽**，抗锯齿把大多数像素与纸混到 180 以上，
低于 160 的所剩无几 —— 于是尾部整段被当成「没有墨」。

| 阈值 | p=0.62 IoU / 面积比 / 重心 | p=1.00 | p=0.20 |
| --- | --- | --- | --- |
| 160 | 0.923 / 1.043 / 3.8px | 0.513 / 0.566 / 97.6px | 0.899 / 0.990 / 12.5px |
| 180 | 0.899 / 1.107 / 1.8px | 0.693 / 0.809 / 21.7px | 0.885 / 1.053 / 18.8px |
| 200 | 0.855 / 1.168 / 2.4px | 0.757 / 0.936 / 12.3px | 0.850 / 1.124 / 26.8px |
| **205** | **约 0.84 / 1.19 / 3px** | **约 0.77 / 0.99 / 11px** | **约 0.83 / 1.16 / 25px** |
| 220 | 0.413 / 2.424 / 50.3px | 0.764 / 1.164 / 2.1px | 0.719 / 1.390 / 31.1px |
| 228 | 0.092 / 10.826 | 0.317 / 3.116 | 0.168 / 5.935 |

220 以上会把纸的格线（约 231）卷进来，面积比暴涨 —— 上界很清楚。

## 3. 注入故障的稳定性

把 `css/base.css` 的全局 `img, svg { max-width: 100% }` 影响重新引入
（即去掉 `.ink` 的 `max-width: none`），在**所有阈值下**：

| 阈值 | 故障 IoU | 故障重心偏差 |
| --- | --- | --- |
| 160 | 0.014 | 219.3px |
| 180 | 0.016 | 206.7px |
| 200 | 0.017 | 204.1px |
| 212 | 0.018 | 208.8px |
| 220 | 0.019 | 197.6px |

IoU ≤0.03、重心偏差 ≈200px，与正确几何（IoU ≥0.77、重心 ≤3% 对角线）
之间余量极大，所以门限不敏感。

## 5. 页面装饰层会污染这条门（用 `?chrome=0` 隔离）

直接量带装饰的截图会失败，因为页面自己的深色元件也算「墨」：

- p=0.40 实测 IoU 0.84 / 重心偏 46.8px —— 字标此刻是 57% 不透明，深色字被算成墨
- p=0.80 实测重心偏 52.8px —— 底部的紫色进度条（`--accent`，亮度约 101）

处置：`js/landing.js` 支持 `?chrome=0`，把顶栏、字标、滚动提示、进度条从 DOM 上
关掉，几何门只在画面本身上跑。

**但这样就不再验证「装饰层有没有把墨压淡」**，所以补一条对照检查：
同一进度取 chrome=0 与带装饰两张图，报 `墨像素比 = 本图 / 对照图`，下限 0.75。

| p | 墨像素比 | 判定 |
| --- | --- | --- |
| 0.40 | 0.979 | 通过 |
| 0.62 | 0.921 | 通过 |
| 1.00 | 1.190 | 通过（带装饰那张还多出 CTA 按钮的深色像素） |

## 6. 限定

只适用于**正常模式**。摊平模式（`≤980px` 或 `prefers-reduced-motion`）下
`.film-pin` 不是 sticky、高度由内容决定，相机取景基准不同，本工具不适用。
